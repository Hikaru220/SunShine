# Гайд по плагину SunShine

Плагин-мост между Minecraft (Paper 1.21.11) и Discord: чат, вход/выход игроков, привязка аккаунтов, вход по подтверждению, приём заявок на сервер с авто-вайтлистом и выдачей ролей.

---

## 1. Команды

### В игре

| Команда | Что делает | Право |
|---|---|---|
| `/sunshine status` | Показывает, подключён ли Discord-бот | Все |
| `/sunshine link` | Выдаёт 4-значный код для привязки Discord-аккаунта | Все |
| `/sunshine unlink` | Отвязывает Discord-аккаунт | Все |
| `/sunshine reload` | Перезагружает `config.yml` без рестарта сервера | `sunshine.admin` (по умолчанию — оп) |
| `/sunshine db-sync` | Заливает все привязки из `linked-accounts.yml` в MySQL-таблицу `player-db` (то же делается автоматически при старте) | `sunshine.admin` |
| `/sunshine admin-unlink <ник>` | Принудительно отвязывает чужой Discord-аккаунт по нику (без рестарта, сразу зеркалится в БД) — для случаев, когда игрок сам отвязать не может | `sunshine.admin` |
| `/profile <ник>` (или `/sunshine profile <ник>`) | Карточка игрока: ник, привязка Discord, время онлайна, группа LuckPerms, кто принял заявку + кликабельные кнопки модерации | `sunshine.profile` |
| `/sunshine punish <ban\|mute\|kick\|warn> <ник> [срок\|-1] [причина]` | Выполняет команду модерации FlectonePulse от лица консоли (см. раздел 9) | `sunshine.profile` |
| `/sunshine lookup <banlist\|mutelist\|warnlist\|geolocate> <ник>` | banlist/mutelist/warnlist — через FlectonePulse и консоль; geolocate — напрямую через ip-api.com, чисто в чат (см. раздел 9) | `sunshine.profile` |

Алиасы: `/ss`, `/sunshinediscord`.

### В Discord

| Команда | Что делает | Право |
|---|---|---|
| `/apply-panel` | Публикует в текущем канале панель с кнопкой "Подать заявку" | Manage Server |
| `/profile <ник>` | Карточка игрока + кнопки модерации (см. раздел 9) | роль из `profile.moderator-role-ids` для кнопок, сама карточка видна всем, кто может выполнить команду |
| `/setup-tickets` | (Sunshine_Support) Публикует панель тикетов техподдержки | Manage Server |
| `/setup-applications` | (Sunshine_Support) Публикует панель заявок на вступление в команду | Manage Server |

## 2. Настройка бота (один раз)

1. [discord.com/developers/applications](https://discord.com/developers/applications) → **New Application** → вкладка **Bot** → **Reset Token**, скопировать — это `bot.token` в конфиге.
2. На вкладке **Bot** включить:
   - `MESSAGE CONTENT INTENT`
   - `SERVER MEMBERS INTENT`
3. Вкладка **OAuth2 → URL Generator**: отметить scope `bot` **и** `applications.commands`, права `Send Messages`, `Manage Messages`, `Embed Links`, `Read Message History`, `Use Slash Commands`. Открыть сгенерированную ссылку — пригласить бота на сервер.
4. Включить режим разработчика в Discord (Настройки → Расширенные), чтобы копировать ID каналов и ролей.

## 3. Что умеет плагин

### Синхронизация чата
Сообщения, входы/выходы игроков и смерти дублируются в Discord-канал (`channels.chat` / `channels.events`). Сообщения из Discord-канала приходят в игровой чат. Опционально — чат может уходить через webhook от лица игрока, см. раздел 8.

### Привязка Discord-аккаунта
- Игрок пишет `/sunshine link` в игре → получает 4-значный код.
- Пишет этот код боту **в личные сообщения** (или в канал `channels.link`, если указан).
- Бот подтверждает привязку и (если включено) удаляет сообщение с кодом из канала.

### Обязательная привязка при входе (SunShineAuth)
`auth.require-link: true` — игрок без привязки получает кик с кодом и инструкцией написать боту в ЛС. Пока не привяжется — на сервер не попадёт.

### Подтверждение входа (2FA)
`auth.require-login-confirmation: true` — привязанному игроку при входе приходит ЛС с кнопками **Подтвердить/Отклонить**, вход держится до ответа (таймаут — `auth.login-confirmation-timeout-seconds`). Подтверждение запрашивается **один раз**, повторно — только если у игрока сменился IP-адрес.

### Заявки на сервер
1. `/apply-panel` в Discord публикует кнопку **"Подать заявку"**.
2. Игрок жмёт кнопку → открывается форма: игровой ник, возраст, откуда узнал, о себе, ознакомлены с правилами.
3. Заявка уходит эмбедом в канал `channels.applications-review` с кнопками **Принять / Отклонить**.
4. **Принять** → игроку в ЛС приходит подтверждение, ник добавляется в вайтлист (`applications.whitelist-command`), выдаётся роль `applications.accepted-role-id`.
5. **Отклонить** → модератор указывает причину → игроку в ЛС приходит причина отказа. Повторно подать заявку после отказа можно (лимит не расходуется навсегда).
6. Вторая роль (`applications.join-role-id`) выдаётся отдельно — только когда принятый игрок реально первый раз зайдёт на сервер.

## 4. Основные ключи config.yml

```yaml
bot:
  token: "..."              # токен бота
  status: "{online}/{max} игроков онлайн"

channels:
  chat: "..."                # канал синхронизации чата
  events: ""                 # канал входов/выходов/смертей (пусто = как chat)
  link: ""                   # доп. канал для кода привязки (необязательно, есть ЛС)
  applications-review: "..." # канал для проверки заявок

auth:
  require-link: false                # обязательна ли привязка Discord для входа
  require-login-confirmation: false  # обязательно ли подтверждение входа в ЛС

applications:
  auto-whitelist: true
  whitelist-command: "whitelist add {player}"  # под SimpleWhitelist и т.п. — поменять команду
  accepted-role-id: ""   # роль сразу при принятии заявки
  join-role-id: ""       # роль после первого реального входа на сервер
```

## 5. Sunshine_Support (тикеты и заявки в команду)

Второй, независимый Discord-бот (свой токен, своя личность), запускаемый внутри этого же плагина/процесса — не требует отдельного хостинга.

- Тикеты: `/setup-tickets` публикует кнопку "Отправить запрос" → выбор темы (Вопрос/Жалоба/Найденный баг/Другое) → форма (ник + описание) → создаётся приватный канал в категории `support.tickets.category-id` (или авто-создаётся категория "Тикеты"), доступный автору и ролям `support.tickets.support-role-ids` (или авто-создаётся роль "Support"). Кнопка "Закрыть тикет" → "Удалить тикет".
- Заявки в команду: `/setup-applications` публикует кнопку "Создать заявку" (доступна только роли `support.staff-applications.required-role-id`, если задана) → форма из 5 вопросов (никнейм, возраст, навыки, мотивация, знание правил) → приватный канал в категории `support.staff-applications.category-id` (или авто-создаётся "Заявки"), доступный ролям `support.staff-applications.reviewer-role-ids` (или авто-создаётся роль "Recruiter").
- Включается через `support.enabled: true` + `support.token` в `config.yml` (см. `support-section-snippet.yml` в корне репозитория).
- Не путать с `/apply-panel` выше — это отдельная функция для заявок на вход на сервер (whitelist), а не набор в команду.

## 6. Файлы данных плагина

- `linked-accounts.yml` — привязки Discord ↔ Minecraft: `discordId`, `lastIp`, `name` (последний ник).
- `applications.yml` — все заявки: статус, ответы, причина отказа, кто и когда принял/отклонил.

Оба файла безопасно оставлять при обновлении jar — новые поля подставляются автоматически, старые данные не теряются.

## 7. Зеркало игроков в MySQL (`player-db`)

`linked-accounts.yml` остаётся основным хранилищем; при `player-db.enabled: true` те же данные дублируются в таблицу MySQL (по умолчанию `sunshine_players`) — чтобы читать их извне (сайт, другой бот).

Таблица создаётся сама:

| колонка | что |
|---|---|
| `uuid` | UUID игрока (PK) |
| `name` | последний ник Minecraft |
| `discord_id` | привязанный Discord, `NULL` после отвязки |
| `last_ip` | последний подтверждённый IP |
| `playtime_seconds` | суммарное время онлайна в секундах |
| `first_seen` / `updated_at` | служебные метки времени |

- Запись обновляется при привязке, подтверждении входа, входе и выходе игрока (upsert, `NULL`-поля не затирают старые значения).
- `playtime_seconds` берётся из плейсхолдера `player-db.playtime-placeholder` (по умолчанию `%flectonepulse_online_total%`) при входе/выходе — нужен **PlaceholderAPI** и **FlectonePulse**. Пустой плейсхолдер = время не отслеживается.
- При старте (и по команде `/sunshine db-sync`) все привязки из `linked-accounts.yml` заливаются в таблицу.
- MySQL-драйвер подтягивается сам через `libraries:` в `plugin.yml`.

## 8. Webhook-чат, консольный мост и group sync (как в DiscordSRV)

### Webhook-чат
`sync.minecraft-to-discord.chat.webhook.enabled: true` — сообщения игрового чата уходят в Discord через channel webhook, от лица игрока (его ник + голова скина как аватар), а не от имени бота. Формат `sync.minecraft-to-discord.chat.format` в этом режиме не применяется (юзернейм/аватар задаёт сам вебхук).

- Требует у бота право **Manage Webhooks** на канале `channels.chat`.
- Плагин сам находит/создаёт вебхук с именем **"SunShine Chat"** на этом канале при первом сообщении; URL кэшируется в памяти на время работы сервера.
- Аватар — с публичного `mc-heads.net` (без ключа), по UUID игрока.
- То же самое можно включить и для входа/выхода/смерти — отдельные флаги `sync.minecraft-to-discord.join.webhook` / `leave.webhook` / `death.webhook` (используют тот же вебхук, канал берётся из `channels.events`). Формат (`join.format`/`leave.format`/`deathFormat`) при этом не отключается — просто дополнительно показываются ник и аватар отправителя.
- Сообщения о смерти защищены от спама: не чаще одного в Discord на игрока раз в 5 секунд — если игрок застрял и умирает по кругу ("death loop"), в канал улетит только первое сообщение, а не сотня одинаковых.
- Ванильный текст смерти (`deathMessage()`) теперь рендерится на русский перед отправкой (раньше уходил как есть, по-английски — Adventure не переводит `Translatable`-компонент сам по себе без явного рендера).

### Консольный мост (`console`)
Дублирует весь вывод консоли сервера в Discord-канал и позволяет выполнять команды из этого канала как команды консоли.

```yaml
console:
  enabled: true
  channel-id: "..."
  command-role-ids:        # можно несколько ролей; старый одиночный command-role-id тоже работает
    - "..."
```

> **⚠️ `command-role-id` — это RCE на сервер через Discord.** Любой участник с этой ролью может выполнить любую команду консоли (`op`, `stop`, `ban` и т.д.) от лица сервера. Указывай только реальную доверенную роль (например "Admin"), никогда — публичную/автовыдаваемую. Пустое значение = команды из Discord не выполняются вообще (по умолчанию отключено, не разрешено всем). Канал не должен быть публично читаемым — в него льётся весь консольный лог (пути, IP при входах, детали ошибок).
>
> Боту на канале нужны права: View Channel, Send Messages, Read Message History, Add Reactions (реагирует ❌ на сообщения от тех, у кого нет роли).

### Group sync (LuckPerms → Discord роли)
Односторонняя синхронизация: смена группы LuckPerms у **привязанного** игрока выдаёт/снимает соответствующую Discord-роль. Обратного направления нет — ручная выдача роли в Discord никак не влияет на группы LuckPerms.

```yaml
group-sync:
  enabled: true
  mappings:
    vip: "123456789012345678"      # luckperms-группа: discord-role-id
    admin: "234567890123456789"
```

Срабатывает при входе игрока на сервер и раз в 5 минут для всех, кто сейчас онлайн. Discord-роли, не упомянутые в `mappings`, плагин не трогает вообще. Требует установленный **LuckPerms** (`softdepend`, если его нет — фича просто ничего не делает и логирует предупреждение один раз).

## 9. /profile — карточка игрока и модерация

`profile.enabled: true` включает Discord-команду `/profile <ник>` и игровые `/profile <ник>` (короткий алиас) и `/sunshine profile <ник>`.

Показывает: ник, привязку Discord (`<@id>` или «не привязан»), сейчас онлайн или нет, статус вайтлиста, суммарное время онлайна (из `player-db`, см. раздел 7 — без него будет «неизвестно»), текущую группу LuckPerms (+ когда истекает, если группа временная), кто/когда принял или отклонил заявку игрока, и **последние наказания** (баны/муты/варны/кики) — читаются напрямую из БД FlectonePulse (`fp_moderation`), см. раздел 10. Вайтлист-статус тоже берётся оттуда (`fp_moderation`, type=WHITELIST), а не из ванильного Bukkit — у FlectonePulse свой вайтлист, не совпадающий с ванильным. Пока FlectonePulse не перенесён на MySQL — история пустая, а вайтлист показывается по запасному ванильному статусу.

Кнопки:
- **Бан / Мут / Кик / Варн** — открывают модалку (срок + причина для бана/мута, только причина для кика/варна) и выполняют настроенную команду FlectonePulse от лица консоли;
- **Список банов / Список мутов / Список варнов** — сразу выполняют `banlist`/`mutelist`/`warnlist <ник>` от лица консоли; ответ приходит туда же, куда обычно отвечает FlectonePulse на консольные команды (смотри консоль сервера, либо консольный Discord-канал из раздела 8, если он включён) — этот вывод обычно нечитаем (сырые коды форматирования), поэтому для геолокации используется отдельный чистый источник, см. ниже;
- **Геолокация** — идёт не через FlectonePulse, а напрямую в [ip-api.com](https://ip-api.com) (бесплатно, без ключа, до 45 запросов/мин) — чистый читаемый результат (страна/город/провайдер/VPN-флаг) сразу в ответе, без консоли;
- **IP** — просто показывает/копирует последний известный IP игрока.

```yaml
profile:
  enabled: true
  # Discord-роли, которым доступны кнопки модерации. Пусто = кнопки скрыты у всех (fail-closed).
  # Можно несколько; старый одиночный moderator-role-id тоже работает.
  moderator-role-ids:
    - "..."
  commands:
    ban: "ban {player} {duration} {reason}"
    mute: "mute {player} {duration} {reason}"
    kick: "kick {player} {reason}"
    warn: "warn {player} {reason}"
    banlist: "banlist {player}"
    mutelist: "mutelist {player}"
    warnlist: "warnlist {player}"
```

Поменяй шаблоны в `commands`, если реальные лейблы команд FlectonePulse на сервере отличаются (алиасы, кастомные команды и т.п.) — `{player}`/`{duration}`/`{reason}` подставляются автоматически, `{duration}` = `-1` (навсегда), если срок не указан.

В игре `/profile <ник>` (или `/sunshine profile <ник>`) выводит ту же карточку в чат:
- `[Бан] [Мут] [Кик] [Варн]` — клик подставляет в строку ввода `/sunshine punish <действие> <ник> ` (дальше нужно дописать срок/причину и отправить самому — Minecraft не даёт вставлять произвольный текст по клику);
- `[Баны] [Муты] [Варны]` — выполняются сразу по клику, без ввода (`/sunshine lookup <banlist|mutelist|warnlist> <ник>`);
- `[Геолокация]` — чистый результат через ip-api.com сразу в чат; `[IP]` — копирует IP в буфер обмена по клику.

**Права:** отдельная нода `sunshine.profile` (default: op) — на `/profile`, `/sunshine profile`, `/sunshine punish`, `/sunshine lookup`. Выдай её через LuckPerms тем модераторам, кто не оп. В Discord дополнительно нужна одна из ролей `moderator-role-ids`. `sunshine.admin` (reload/db-sync/admin-unlink) — отдельное право, не связано с `/profile`.

## 10. Перенос БД FlectonePulse из H2 в MySQL

По умолчанию FlectonePulse хранит всё (включая историю банов/мутов/варнов) во встроенном файле H2 — прочитать его снаружи (для настоящей истории наказаний в `/profile`, а не только кнопок-шорткатов) нельзя, пока он лежит в H2: второе подключение к живому H2-файлу рискует его повредить. Команда `/sunshine migrate-flectonepulse` переносит все данные в ту же MySQL, что уже занята под `player-db` (у таблиц FlectonePulse свой префикс `fp_`, коллизий нет — отдельный слот БД не нужен).

**⚠️ Делать строго по шагам, не пропускать:**

1. Останови сервер.
2. **Убери jar FlectonePulse из `plugins/`** (переименуй/перенеси куда-то, не удаляй совсем).
3. Запусти сервер — FlectonePulse не загрузится, его H2-файл никем не занят.
4. В консоли сервера выполни:
   ```
   sunshine migrate-flectonepulse <путь_к_файлу_без_.mv.db> [h2-юзер] [h2-пароль]
   ```
   Путь — тот же, что у файла `<имя>.h2.mv.db`, но без расширения, например
   `plugins/FlectonePulse/database/flectonepulse.h2` (если файл называется `flectonepulse.h2.mv.db`).
   `h2-юзер`/`h2-пароль` можно не указывать — по умолчанию пробуются `sa` / пусто (стандартные для H2, если FlectonePulse не задавал свои).
5. Дождись `Готово!` в консоли — команда сама создаст таблицы FlectonePulse в MySQL и перенесёт все строки, сохранив ID.
6. Останови сервер.
7. Верни jar FlectonePulse обратно в `plugins/`.
8. В `config.yml` FlectonePulse (`database:`) поставь:
   ```yaml
   database:
     type: "MySQL"          # было H2
     name: "..."             # то же имя БД, что у player-db.name в SunShine
     host: "..."              # то же, что player-db.host
     port: 3306
     user: "..."              # то же, что player-db.user
     password: "..."          # то же, что player-db.password
   ```
9. Запусти сервер. FlectonePulse подключится к MySQL и увидит уже перенесённые данные — история банов/мутов/варнов и время игры сохранены.

После этого можно попросить дополнительно научить `/profile` показывать настоящую историю наказаний (читать `fp_moderation` напрямую) — раньше это было невозможно без риска для живого H2-файла, теперь база сетевая и доступна безопасно.
